Performance et optimisation

Guide pour optimiser les performances de vos intégrations avec l'API GestAgro.

Pagination efficace

Utilisez toujours la pagination pour les grandes listes. Ne chargez que les données nécessaires. 

// Requête paginée
GET {{ api_base_url }}farmers/products/?page=1&page_size=20

// Réponse
{
  "count": 250,
  "next": "{{ api_base_url }}farmers/products/?page=2&page_size=20",
  "previous": null,
  "results": [...]
}

Astuce : Ajustez page_size selon vos besoins (max 100 par défaut).

Mise en cache

Stratégies de cache

  • Données statiques : Catégories, configurations (TTL: 24h)
  • Données semi-statiques : Produits, utilisateurs (TTL: 1h)
  • Données dynamiques : Commandes, statistiques (TTL: 5-15min)
  • Ne jamais mettre en cache : Tokens, données sensibles

Headers de cache

Respectez les headers Cache-Control et ETag dans les réponses de l'API. 

// Requête conditionnelle avec ETag
GET /api/v1/farmers/products/
If-None-Match: "abc123..."

// Si non modifié, réponse 304 Not Modified (pas de données transférées)

Requêtes parallèles

Lorsque vous devez récupérer plusieurs ressources indépendantes, effectuez les requêtes en parallèle plutôt qu'en série. 

// Série (lent)
const products = await fetch('/products');
const orders = await fetch('/orders');
const stats = await fetch('/stats');

// Parallèle (rapide)
const [products, orders, stats] = await Promise.all([
  fetch('/products'),
  fetch('/orders'),
  fetch('/stats')
]);

Attention : Respectez les limites de rate limiting même avec des requêtes parallèles.

Filtrage efficace

Utilisez les paramètres de filtrage pour réduire la taille des réponses et améliorer les performances.

Filtres par champ

GET /products/?status=active&category=1

Recherche full-text

GET /search/products/?q=tomate

Tri

GET /products/?ordering=-created_at,price

Plage de dates

GET /orders/?created_at__gte=2025-01-01

Compression

L'API supporte la compression gzip et brotli. Ajoutez les headers appropriés pour réduire la taille des réponses. 

GET /api/v1/farmers/products/
Accept-Encoding: gzip, br

// La réponse sera compressée automatiquement

Optimisations avancées

Connection pooling

Réutilisez les connexions HTTP pour éviter le coût d'établissement de nouvelles connexions.

Timeouts appropriés

Configurez des timeouts adaptés (connect: 5s, read: 30s) pour éviter les blocages.

Batch requests

Utilisez les endpoints batch quand disponibles pour réduire le nombre de requêtes.

Lazy loading

Chargez les données seulement quand elles sont nécessaires (infinite scroll, etc.).
