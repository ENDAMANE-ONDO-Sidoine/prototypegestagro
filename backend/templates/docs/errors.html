Gestion des erreurs

L'API GestAgro utilise les codes de statut HTTP standard pour indiquer le succès ou l'échec d'une requête. Cette page détaille tous les codes d'erreur possibles et comment les gérer.

Codes de succès

Code Description Usage
200 OK Requête réussie
201 Created Ressource créée avec succès
204 No Content Requête réussie, pas de contenu à retourner

Erreurs client (4xx)

400

Bad Request

La requête est mal formée ou contient des paramètres invalides.

{
  "detail": "Les champs suivants sont requis: email, password",
  "errors": {
    "email": ["Ce champ est requis."],
    "password": ["Ce champ est requis."]
  }
}

Solution : Vérifiez la structure de votre requête et tous les champs obligatoires.

401

Unauthorized

Token d'authentification manquant, invalide ou expiré.

{
  "detail": "Les identifiants d'authentification n'ont pas été fournis.",
  "code": "authentication_failed"
}

Solution : Vérifiez que vous incluez le header Authorization: Bearer <token> ou reconnectez-vous.

403

Forbidden

Vous n'avez pas les permissions nécessaires pour effectuer cette action.

{
  "detail": "Vous n'avez pas la permission d'effectuer cette action.",
  "code": "permission_denied"
}

Solution : Vérifiez votre rôle utilisateur et les permissions de votre organisation.

404

Not Found

La ressource demandée n'existe pas ou n'est pas accessible.

{
  "detail": "Pas trouvé.",
  "code": "not_found"
}

Solution : Vérifiez l'URL et l'ID de la ressource. Assurez-vous que vous avez accès à cette ressource.

429

Too Many Requests

Vous avez dépassé le nombre maximum de requêtes autorisées.

{
  "detail": "Requête refusée en raison d'un taux de requêtes trop élevé.",
  "retry_after": 60
}

Solution : Attendez le délai indiqué dans retry_after (en secondes) avant de réessayer.

Documentation complète sur le rate limiting →

Erreurs serveur (5xx)

500

Internal Server Error

Une erreur inattendue s'est produite côté serveur.

{
  "detail": "Une erreur interne du serveur s'est produite.",
  "error_id": "ERR-2025-10-29-123456"
}

Solution : Réessayez plus tard. Si le problème persiste, contactez le support avec l'error_id.

Gestion des erreurs dans votre code

JavaScript (Fetch)

async function makeRequest(url, token) {
  try {
    const response = await fetch(url, {
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      }
    });
    
    if (!response.ok) {
      const error = await response.json();
      
      switch (response.status) {
        case 401:
          // Token expiré, rafraîchir
          await refreshToken();
          break;
        case 404:
          console.error('Ressource non trouvée:', error.detail);
          break;
        case 429:
          const retryAfter = error.retry_after;
          await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
          return makeRequest(url, token); // Réessayer
        default:
          console.error('Erreur:', error);
      }
      
      throw new Error(error.detail || 'Une erreur est survenue');
    }
    
    return await response.json();
  } catch (error) {
    console.error('Erreur réseau:', error);
    throw error;
  }
}

Python (Requests)

import requests
from time import sleep

def make_request(url, token):
    headers = {
        'Authorization': f'Bearer {token}',
        'Content-Type': 'application/json'
    }
    
    try:
        response = requests.get(url, headers=headers)
        response.raise_for_status()
        return response.json()
    
    except requests.exceptions.HTTPError as e:
        error_data = response.json() if response.content else {}
        
        if response.status_code == 401:
            # Token expiré, rafraîchir
            token = refresh_token()
            return make_request(url, token)
        
        elif response.status_code == 429:
            retry_after = error_data.get('retry_after', 60)
            sleep(retry_after)
            return make_request(url, token)
        
        else:
            raise Exception(error_data.get('detail', str(e)))
    
    except requests.exceptions.RequestException as e:
        raise Exception(f'Erreur réseau: {str(e)}')

Bonnes pratiques

  • Toujours vérifier le code de statut HTTP avant de traiter la réponse
  • Implémenter une gestion d'erreur robuste avec retry pour les erreurs temporaires (429, 500)
  • Logger les erreurs avec l'error_id pour faciliter le débogage
  • Gérer automatiquement le rafraîchissement des tokens expirés (401)
  • Afficher des messages d'erreur clairs et utiles à l'utilisateur final
