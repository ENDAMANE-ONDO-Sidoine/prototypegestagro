Bonnes pratiques

Guide des meilleures pratiques pour utiliser l'API GestAgro efficacement et de manière sécurisée.

Gestion des erreurs

Implémenter une logique de retry

Les erreurs temporaires (429, 500, 503) nécessitent une logique de retry avec backoff exponentiel. 

// JavaScript/Node.js
async function apiRequest(url, options, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      const response = await fetch(url, options);
      if (response.ok) return response;
      
      // Retry seulement pour erreurs temporaires
      if (response.status === 429 || response.status >= 500) {
        const delay = Math.pow(2, i) * 1000; // Backoff exponentiel
        await new Promise(resolve => setTimeout(resolve, delay));
        continue;
      }
      throw new Error(`HTTP ${response.status}`);
    } catch (error) {
      if (i === retries - 1) throw error;
    }
  }
}

Vérifier les headers de réponse

Les headers contiennent des informations importantes :

  • X-RateLimit-Remaining : Requêtes restantes
  • Retry-After : Secondes à attendre après erreur 429
  • X-Request-ID : ID unique pour le support

Gestion des tokens

Refresh automatique

Implémentez un mécanisme de refresh automatique avant l'expiration du token. 

// Python
import time
from datetime import datetime, timedelta

class TokenManager:
    def __init__(self):
        self.access_token = None
        self.refresh_token = None
        self.expires_at = None
    
    def is_token_expired(self):
        if not self.expires_at:
            return True
        return datetime.now() >= self.expires_at - timedelta(minutes=5)  # Refresh 5min avant
    
    async def get_valid_token(self):
        if self.is_token_expired():
            await self.refresh_access_token()
        return self.access_token

Stockage sécurisé

  • Ne jamais stocker les tokens en clair dans le code source
  • Utiliser des variables d'environnement ou un gestionnaire de secrets
  • En production web, utiliser des cookies httpOnly ou le localStorage de manière sécurisée
  • Ne jamais exposer les tokens dans les logs ou les URLs

Optimisation des requêtes

Utiliser la pagination

Ne chargez que les données nécessaires en utilisant les paramètres de pagination. 

// Requête avec pagination
GET {{ api_base_url }}farmers/products/?page=1&page_size=20

// Réponse
{
  "count": 150,
  "next": "{{ api_base_url }}farmers/products/?page=2",
  "previous": null,
  "results": [...]
}

Utiliser les filtres et la recherche

Réduisez la taille des réponses en utilisant les paramètres de filtrage disponibles. 

// Filtrer par statut
GET {{ api_base_url }}farmers/products/?status=active

// Recherche
GET {{ api_base_url }}search/products/?q=tomate&category=legumes

// Tri
GET {{ api_base_url }}farmers/products/?ordering=-created_at

Éviter les requêtes N+1

Utilisez les endpoints dédiés plutôt que de faire plusieurs requêtes séquentielles.

À éviter :

for product in products: get_product_details(product.id)

Recommandé :

GET /farmers/products/ (retourne tous les détails)

Sécurité

HTTPS uniquement

Utilisez toujours HTTPS en production. L'API refuse les connexions non sécurisées.

Validation des données

Validez toujours les données avant de les envoyer à l'API pour éviter les erreurs 400.

Permissions minimales

Utilisez des tokens avec les permissions minimales nécessaires pour votre cas d'usage.

Gestion des secrets

Ne commitez jamais vos tokens ou clés API dans votre gestionnaire de version.

Performance

Mise en cache

Mettez en cache les données qui changent rarement (catégories, configurations, etc.).

  • Respectez les headers Cache-Control
  • Utilisez ETag pour la validation conditionnelle
  • Ne mettez pas en cache les données sensibles ou personnelles

Requêtes parallèles

Lorsque possible, effectuez plusieurs requêtes en parallèle plutôt qu'en série. 

// JavaScript - Requêtes parallèles
const [products, orders, stats] = await Promise.all([
  fetch('{{ api_base_url }}farmers/products/'),
  fetch('{{ api_base_url }}buyers/orders/'),
  fetch('{{ api_base_url }}farmers/dashboard/stats/')
]);

Checklist de vérification

Avant le déploiement :

  • Tokens stockés de manière sécurisée
  • HTTPS activé en production
  • Gestion des erreurs implémentée
  • Refresh automatique des tokens
  • Rate limiting respecté

Optimisation :

  • Pagination utilisée pour les grandes listes
  • Filtres et recherche utilisés
  • Cache mis en place pour données statiques
  • Requêtes parallèles quand possible
  • Logs configurés pour le débogage
